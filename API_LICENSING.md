## Provider assessment

Contract correction, checked against the official endpoint specifications on 8 October 2026: MovieGlu `filmShowTimes` returns `cinema.showings` as an object keyed by screening format (for example `Standard` and `3D`), with each value holding its `times` array. Watchmode's current title-release-date schema says `verification_status` is null for theatrical rows; that status describes digital provider verification. The adapter therefore accepts theatrical rows only when `type` is `theatrical_release`, `title_type` is `movie`, the territory matches the request, the date is a real ISO calendar date, and the Watchmode ID maps to an approved, horror-verified canonical film. It never uses the provider's arbitrary row title for streaming release publication; only an approved exact ID mapping can supply a public title.

## Licensed critic-review feed status

A server-side, allowlisted normalized-feed adapter has been prepared in `worker/review-ingestion.js`; it is disabled by default and has no provider credentials. It accepts only numeric critic review records whose score reuse is licensed, stages new reviews for editorial approval, and holds corrections/withdrawals in a separate review queue. It does not scrape protected websites. See `LICENSED_REVIEW_FEED.md` for the response contract, secret names, staging process and owner setup steps. The 2026 public ranking remains pending until eligible records are lawfully acquired and approved.

## Publication and ranking safeguards

- Feed data is published only after schema checks pass. Dataset snapshots include source, territory, checked date and expiry. The pointer changes only after a complete valid snapshot is written. Failed updates are logged and leave the last valid snapshot in place; expired data is labelled stale.
- Provider discovery produces a pending human-review candidate. It does not publish a film record or assert that a candidate is a horror film for editorial purposes.
- Critic rows require numeric professional scores, a source review link, publication, critic identity, territory, dates, explicit permission attestation and professional verification. The administrative write endpoint is secret protected and records a permission evidence URL. An editor still must review and approve each row.
- At most one score per distinct critic, film and release year contributes. Canonical review URLs prevent a duplicate review or syndicated URL from counting twice. Each score is converted to /100; eligible critics receive equal weight; the arithmetic mean is rounded to the nearest whole number. A film needs at least three eligible critics. No eligible rows means “pending.”
- Audience ratings, Rotten Tomatoes positive percentages, Metacritic weighted scores, provider popularity and provider ratings are excluded from Fright Index calculations.
- Showtimes are retrieved only by an on-demand request for an approved film, chosen country, current date and visitor-provided coordinates. MovieGlu showtime responses are not cached. The UI separately labels release-date-only items as recent theatrical releases.
- Cinema requests are limited to 10 per client digest per minute. D1 stores a salted HMAC of the request address rather than the raw address, and old limiter rows are pruned daily. The `CINEMA_RATE_LIMIT_SALT` Worker secret must be set before the live route can call MovieGlu; without it the route fails closed.
- Digital release events are shown by country and state. “Streaming-first,” “direct-to-video” and “theatrical-then-streaming” are controlled editorial classifications that remain “unconfirmed” without a separately sourced approval.
- API keys and admin tokens are read only from Worker bindings/secrets. None belongs in browser JavaScript, committed files or build output. Test fixture data is synthetic, explicitly marked and imported only by `node:test`; it is never part of site data or ingestion.

## Owner actions before activation

1. Obtain written commercial approval and accounts for Watchmode, MovieGlu and (if used) TMDB. Confirm licensed territories, endpoint quotas, attribution, caching, retention, image restrictions and the current price in each agreement.
2. Decide how to obtain permission-cleared numeric critic ratings. If a commercial feed is chosen, secure and document its licence. Otherwise configure an editor to enter scores with evidence URLs and approve them manually. Do not scrape critic-score sites.
3. Before production use, provision a production Worker and D1 database separately from the existing private staging resources; apply and verify migrations, bindings, access policy, plan, Cron schedule and retention. The checked-in `wrangler.jsonc` is local development configuration and its all-zero `database_id` placeholder must not be treated as a real resource ID or replaced with a production ID in source.
4. Set `DISCOVERY_COUNTRIES` to only countries covered by active provider licences (comma-separated ISO 3166-1 alpha-2 codes). The default is `GB` only. Add corresponding country choices to `index.html` as licenses are approved.
5. Configure D1 binding/migrations, then set credentials as Worker secrets: `ADMIN_TOKEN`, `CINEMA_RATE_LIMIT_SALT`, `TMDB_READ_ACCESS_TOKEN`, `MOVIEGLU_API_KEY`, `MOVIEGLU_AUTHORIZATION`, and Watchmode `WATCHMODE_API_KEY`. Set non-secret approval/plan vars only after the contract is active: `TMDB_COMMERCIAL_LICENSE_APPROVED`, `TMDB_ATTRIBUTION_READY`, `MOVIEGLU_LICENSE_APPROVED`, `WATCHMODE_LICENSE_APPROVED`, `WATCHMODE_PLAN`, plus MovieGlu `MOVIEGLU_CLIENT` and current `MOVIEGLU_API_VERSION`.
6. Supply and place the official TMDB attribution logo, display the required non-endorsement notice, and confirm the contract attribution text before enabling TMDB data. Set a suitable Cloudflare rate limit for the public showtime API to control licensed provider usage. The private preview already has a Pages Function and a separate staging Worker; do not alter either deployment as part of local development. Connect any future production route only after an owner approves provider/legal setup and separately authorizes production deployment. `workers_dev` is disabled and the production domain/DNS is not modified by this repository.
7. Confirm the weekly update review process, set a strong random admin token, restrict access to the administrative endpoints at the host/identity layer if available, and rotate secrets through Cloudflare after staffing changes.

Local QA can run without those accounts. Provider adapters fail closed; the frontend says listings are unavailable, and ranking pages remain pending until cleared data is entered. Do not deploy the checked-in local configuration: its zero UUID is a deliberate placeholder. The private staging deployment is a separate owner-managed resource and must remain isolated from production.
