# Seven-page visual baseline — 2026-10-13

Baseline commit: `f9a2de86d3c2897a5e481b39d9e07fd3687b8689` (`codex/seven-page-implementation`). The first 28 captures were made before application files changed. Later intermediate-width checks used a read-only `git archive` of the same commit, served on port 4174. No application code or tests were changed for this baseline.

## Capture conditions

- Chromium `151.0.7922.173` through Python Playwright; CSS viewports `390×844` and `1440×900`, device-pixel ratio `1`, default browser zoom, dark scheme and reduced motion. Additional first-viewport checks used `320`, `768` and `980` CSS-pixel widths. These are browser simulations, not a physical phone or phone desktop-site mode.
- First viewport and full page were captured after DOM content loaded and a 2.2-second wait. Requested URLs and final URLs matched for `/`, `/movies.html`, `/tv-shows.html`, `/cinema.html`, `/indie-movies.html`, `/podcasts.html` and `/games.html` on the local static server.
- Local Python static serving has **no `/api/` backend**. Rankings, catalogue, podcast and media requests returned HTTP 404. The watchlist was empty. Cinema's source-checked screening JSON and static editorial data loaded. No JavaScript page exceptions were recorded. The captures therefore show genuine local fallback states, with first-party editorial artwork and no fetched official posters or ratings. They do not verify authenticated preview data.
- [Raw measurements](before/baseline-measurements.json), [intermediate measurements](before/baseline-detail-measurements.json) and [Cinema identity reproduction](before/baseline-cinema-identity.json) retain browser, route, final URL, width, data response and box details.

## Reproduced findings

1. **Cinema can become Movies after delayed initialization on an extensionless URL.** Baseline `cinema.html` declares `data-theme="movies"`; `v5-magazine.js` treats only paths ending in `/cinema.html` as Cinema. Direct `/cinema.html` kept the country selector and diary in place. A controlled rewrite serving the unchanged `cinema.html` at `/cinema` preserved the extensionless browser URL. After the script's 7.5-second wait for a nonexistent carousel, it inserted `EXPLORE MOVIES`, My Watchlist, Top 20 and trailer modules before the Cinema content, then moved the Cinema sections into a disclosure. [390 screenshot](before/cinema-390-extensionless-rewrite.png), [980 screenshot](before/cinema-980-extensionless-rewrite.png). The local Python server does not itself implement extensionless rewrites, so support and redirect behaviour on the protected Pages deployment still needs verification. The controlled rewrite establishes the code-path failure.
2. **Indie and Podcast editorial composition cuts content at intermediate widths.** At 768px, [Indie](before/indie-movies-768-detail.png) and [Podcasts](before/podcasts-768-detail.png) show cropped portrait artwork, almost no synopsis, and a file block beneath the compressed content. The Indie synopsis has `clientHeight=0` and `scrollHeight=151`; Podcasts has approximately `9` vs `50` pixels. At 980px, Indie has approximately `12` vs `101` pixels, and Podcasts `25` vs `50` pixels ([Indie](before/indie-movies-980-detail.png), [Podcasts](before/podcasts-980-detail.png)). The baseline CSS imposes a 310px `!important` height on `.editorial-pick`, constrains its art frame, hides overflow in its content, and clamps synopsis. The Podcast fallback also uses the same 2:3 portrait slot as films. At 390px, both pages show only a short two-line synopsis; this is visually compressed but the intermediate width is the unambiguous complete-loss defect. The source text remains in the DOM, yet it is not visibly readable.
3. **Movies masthead is sensitive to widths.** At 390 and 1440 the wordmark is visible. At 980px [the eyebrow is partly behind/clipped by the header](before/movies-980-detail.png). At 320px [the rightmost jump link is cut](before/movies-320-detail.png). The fixed-height, `overflow:hidden` masthead has `scrollHeight=228` vs `clientHeight=225` at 1440. Font-unavailable and open menu/search states were not yet captured.
4. **Home chart/fold balance cannot be fully judged with real ranking data locally.** At 1440px [feature and ranking fallback](before/home-desktop1440-first.png) occupy a `350px` row, but `#hub-ranking` is an inner scroll area (`clientHeight=136`, `scrollHeight=164`) even for its fallback message; the CSS also caps its normal height at 200px. A five-film populated preview remains unverified. The Home intro itself has `scrollHeight=290` vs `clientHeight=259` with hidden overflow. At 390px the chart follows the feature and five category tiles, with a readable unavailable state, but the separate detail/attribution bands remain visually large relative to the data. The lower update/discovery disclosures are functional-looking but plain and boxed in this state.
5. **All seven page mastheads reuse the haunted estate scene.** The inner-page CSS hardcodes `concept-haunted-house.png` for Movies, TV, Cinema, Indie, Podcasts and Games. Their editorial background scenes differ, but the first page-defining image does not. Cinema therefore reads as a mansion rather than an auditorium. The same red treatment and repeated dark rectangular fallback panels weaken page distinction.
6. **Unavailable data leaves oversized empty surfaces.** The Movies, TV and Indie catalogue fallback panels retain large fixed space around a narrow paragraph; see their full-page captures. The Cinema diary and recent-release panels also hold substantial blank space with only an error message and retry button. These are local unavailable states and should be assessed separately from populated preview behaviour.
7. **No horizontal document overflow was measured at 390 or 1440.** Both document scroll widths matched the viewport. This does not mean internal content fits; the editorial synopsis and mastheads are clipped inside their own boxes. The fixed mobile dock appears as a horizontal line partway down full-page screenshots because the browser captures it at the initial viewport position.

## Remaining baseline limits

Authenticated protected-preview data, official poster/cover hydration, loaded rankings, populated watchlists, normal phone desktop-site mode, Safari/Firefox and physical devices were not available in this read-only local baseline. The Cinema extensionless case was a controlled browser rewrite, not a claim about the current Pages redirect configuration. All screenshot links above are **before** images; subsequent fixes need separate after captures and an exact deployed-SHA check.
